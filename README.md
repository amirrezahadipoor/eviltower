# برج شیطانی — Evil Tower

<div dir="rtl">

یک بازی اکشن-آرکید عمودیِ صعود از برج، برای اندروید، با **Kotlin + Jetpack Compose**.
تمام متن‌ها، داستان و رابط کاربری **فارسی و راست‌به‌چپ (RTL)** است و تمام گرافیک بازی
**برداری (SVG/Vector) و متحرک** است. مقصد انتشار: **کافه بازار**.

</div>

> A vertical tower-climbing action/arcade game for Android: procedurally generated floors,
> "one mistake sends you back to the ground floor", rogue-lite meta progression, animated
> vector art, Persian RTL UI and a Cafe Bazaar (Poolakey) release pipeline.

| | |
| --- | --- |
| Package | `ir.hadipoor.eviltower` |
| Language / UI | Kotlin, Jetpack Compose (Material 3) |
| Min / Target SDK | 24 (Android 7.0) / 35 |
| Orientation | Portrait-locked |
| Store target | Cafe Bazaar (کافه بازار) — **no Google Play Services** |
| Billing | Cafe Bazaar **Poolakey** 2.2.0 (Google Play Billing is *not* used) |
| APK builds | GitHub Actions → *Actions* tab → latest run → **Artifacts** |

## ۱. نصب و اجرا / Build & run

```bash
git clone https://github.com/amirrezahadipoor/eviltower.git
cd eviltower

./gradlew assembleDebug      # debug APK  -> app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # release APK -> app/build/outputs/apk/release/app-release.apk
./gradlew test               # unit tests (generation, collision, playability simulation)
```

Requirements: **JDK 17**, Android SDK 35 (Android Studio Ladybug or newer). No manual steps are
needed — the project builds from a clean clone.

### APK از گیت‌هاب

هر push روی `main` توسط ورک‌فلو [`.github/workflows/build.yml`](.github/workflows/build.yml)
ساخته می‌شود و سه خروجی می‌دهد:

* `eviltower-debug-apk` — نسخه‌ی دیباگ برای نصب سریع روی گوشی
* `eviltower-release-apk` — نسخه‌ی انتشار (کوچک‌شده با R8، امضاشده)
* `unit-test-report` — گزارش تست‌ها

همچنین آخرین APKها به‌صورت خودکار در بخش **Releases** مخزن منتشر می‌شوند.

## ۲. معماری / Architecture

```
app/src/main/java/ir/hadipoor/eviltower/
├── MainActivity.kt              میزبان تک‌اکتیویتی + سنسور شیب + اتصال بازار
├── ui/
│   ├── EvilTowerApp.kt          ناوبری بین صفحه‌ها، تزریق زبان و جهت RTL
│   ├── GameViewModel.kt         MVVM: پروفایل، تنظیمات، چرخه‌ی عمر یک صعود
│   ├── Strings.kt               تمام متن‌های بازی (فارسی/انگلیسی)
│   ├── components/              دکمه‌ها، پنل سنگی، آیکون‌های برداری متحرک
│   ├── screens/                 اسپلش، منو، بازی، فروشگاه، تنظیمات، دستاوردها، رکوردها، پایان بازی
│   └── theme/                   پالت، تایپوگرافی وزیرمتن، تم تیره
├── game/
│   ├── model/Entities.kt        AABB، بازیکن، دشمن، تله، سکو، آیتم، رویدادها
│   ├── engine/GameConfig.kt     تمام اعداد قابل تنظیم بازی
│   ├── engine/FloorGenerator.kt تولید رویه‌ای طبقات (۱۳ الگو)
│   ├── engine/GameEngine.kt     فیزیک، برخورد، هوش دشمنان، دوربین، پیشرفت
│   └── render/                  کتابخانه‌ی SVG، پالت پوسته‌ها، رندرکننده‌ی ۶۰fps
├── data/                        DataStore، فروشگاه، دستاوردها
├── audio/GameAudio.kt           SoundPool + MediaPlayer + لرزش
└── monetization/                AdProvider (استاب) و BillingProvider (Poolakey بازار)
```

**MVVM با مرز روشن:**

* `GameEngine` — شبیه‌سازی خالص Kotlin، بدون هیچ وابستگی به اندروید ⇒ کاملاً تست‌پذیر.
* `GameViewModel` — وضعیت ماندگار، تنظیمات، صدا، شروع/پایان صعود.
* Composables — فقط رسم و ورودی؛ حلقه‌ی بازی با `withFrameNanos` اجرا می‌شود و
  مقادیر پرتکرار (زمان، شمارنده‌ی فریم) خارج از Compose state نگه داشته می‌شوند تا
  در هر فریم recomposition رخ ندهد.

## ۳. رویکرد گرافیک برداری (انتخاب فنی) / SVG animation approach

**رویکرد انتخاب‌شده: «داده‌ی مسیر SVG → `PathParser` → رسم روی Compose Canvas با انیمیشن رویه‌ای».**

چرا این رویکرد و نه `AnimatedVectorDrawable`؟ AVD برای آیکون‌های UI عالی است اما برای ده‌ها
سوژه‌ی متحرک با حالت‌های مختلف (idle/run/jump/attack/hit/death) در یک حلقه‌ی ۶۰ فریمی گران و
غیرقابل کنترل می‌شود. در این پروژه:

1. هر سوژه به‌صورت **داده‌ی مسیر SVG** در یک view-box ‍`100×100` در
   [`SvgSprites.kt`](app/src/main/java/ir/hadipoor/eviltower/game/render/SvgSprites.kt) نوشته شده است.
2. رشته‌های مسیر **یک بار** با `PathParser` به `Path` تبدیل و در `SpriteCache` نگه‌داری می‌شوند —
   هیچ مسیری در هیچ فریمی دوباره parse نمی‌شود.
3. انیمیشن با ماتریس تبدیل انجام می‌شود: چرخش اندام‌ها، بال‌زدن، squash & stretch، تیغه‌ی چرخان،
   شعله‌ی لرزان، سکه‌ی چرخان و…
4. همین مسیرها به‌صورت فایل‌های واقعی `.svg` در `app/src/main/assets/svg/` صادر می‌شوند
   (با `python3 tools/export_svg.py`) تا در Inkscape/Figma قابل ویرایش باشند.

حالت‌های انیمیشن هر شخصیت: `IDLE`, `RUN/MOVE`, `JUMP`, `ATTACK`, `HIT`, `DEATH`
(برای بازیکن `FALL` هم اضافه است).

آیکون‌های UI (قلب، سکه، جواهر، سپر، بال…) از همان مسیرها ساخته می‌شوند و با
`SvgIcon(animation = IconAnimation.Spin / Pulse / Float / Rotate)` متحرک‌اند.
پس‌زمینه لایه‌های متحرک دارد: مشعل‌های سوسوزن با هاله، مه شناور، ذرات خاکستر و آجرهای پارالاکس.

### افزودن گرافیک جدید

```kotlin
// 1) داده‌ی مسیر را در SvgPaths اضافه کن (view-box 100x100، رو به راست)
const val GHOST_BODY = "M50,10 C70,10 ..."
// 2) فایل svg را بساز
//    python3 tools/export_svg.py
// 3) هرجا لازم شد رسمش کن
drawSvg(SvgPaths.GHOST_BODY, x, y, w, h, color, rotation = angle, flipX = facingLeft)
```

نام‌گذاری: `<SUBJECT>_<PART>` مثل `HERO_TORSO`, `BAT_WING`, `TRAP_BLADE`
→ فایل صادرشده: `assets/svg/hero_torso.svg`.

## ۴. طراحی بازی / Gameplay

* **هدف:** از طبقه ۱ تا طبقه ۱۰۰ بالا برو و ارباب برج را شکست بده.
* **حرکت:** حرکت آزاد افقی + پرش؛ هر طبقه ۱۵۰ واحد ارتفاع دارد و با ۵ سکوی پلکانی
  (فاصله‌ی عمودی ۲۴ واحد) طی می‌شود. ارتفاع پرش ≈ ۳۱٫۸ واحد و برد افقی پرش ≈ ۳۲ واحد است؛
  ژنراتور تضمین می‌کند هیچ فاصله‌ای از این مقادیر بیشتر نشود (تست واحد این را می‌سنجد).
* **جان:** ۳ قلب (با ارتقای «قلب اضافه» تا ۵). برخورد با تله یا دشمن یک قلب کم می‌کند و
  یک ثانیه مصونیت می‌دهد. **تمام‌شدن قلب‌ها = سقوط تا کف برج و پایان صعود.**
* **سقوط:** افتادن بیش از ۱٫۳۵ طبقه پایین‌تر از بلندترین نقطه‌ی رسیده = پایان صعود
  (همان مکانیک بی‌رحم «بدون نقطه‌ی ذخیره»).
* **حمله:** ضربه با شمشیر (لمس صفحه) یا پریدن روی سر دشمن (stomp).
* **باس‌ها:** هر ۱۰ طبقه «دیو دروازه‌بان» و هر ۲۵ طبقه «ارباب برج» (سه‌مرحله‌ای، در فاز
  دوم خفاش احضار می‌کند). تا شکست‌دادن باس، دروازه‌ی طبقه قفل است.
* **امتیاز:** `بلندترین طبقه × ضریب سختی × ۱۰ + سکه‌ها`.

### الگوهای طبقه (۱۳ عدد)

پلکان سنگی، پل شکسته، گذرگاه شکننده، راهروی تیغه‌ها، تالار آتش، دروازه له‌کننده،
سکوهای لرزان، لانه مار سنگی، غار خفاش‌ها، کنام گرگ سایه، تالار خواب‌آور،
میدان دروازه‌بان (مینی‌باس)، تالار ارباب برج (باس).

وزن هر الگو با شماره‌ی طبقه تغییر می‌کند: هرچه بالاتر، فاصله‌ها بیشتر، سکوها باریک‌تر،
تیغه‌ها سریع‌تر، دشمنان بیشتر و روشنایی کمتر.

### افزودن الگوی طبقه‌ی جدید

<div dir="rtl">

۱. یک عضو جدید به `FloorGenerator.FloorTemplate` با نام فارسی اضافه کن.
۲. در `decorate()` تله‌ها/دشمنان آن را بچین.
۳. در جدول وزن‌دار `pickTemplate()` واردش کن.
همه‌ی بخش‌های دیگر (چیدمان سکوها، تضمین قابل‌عبوربودن، دوربین، برخورد) خودکار کار می‌کنند.

</div>

### افزودن دشمن جدید

```kotlin
// 1) EnemyKind: نام فارسی + اندازه در FloorGenerator.spawnEnemy
// 2) رفتار در GameEngine.updateEnemy(...)
// 3) گرافیک در GameRenderer.drawEnemy(...) با مسیرهای SvgPaths
```

## ۶. صدا / Audio

تمام صداها **به‌صورت رویه‌ای ساخته شده‌اند** (بدون فایل صوتی شخص ثالث):
`python3 tools/generate_audio.py` → ۱۴ افکت (`res/raw/sfx_*.wav`) و یک موسیقی حلقه‌ای
بی‌درز (`res/raw/music_tower.wav`).

* SFX با `SoundPool` (۸ استریم هم‌زمان)
* موسیقی با `MediaPlayer` (بدون ExoPlayer ⇒ APK سبک‌تر و بدون وابستگی گوگل)
* لرزش با `Vibrator` روی ضربه، غرش باس و سقوط

## ۷. ذخیره‌سازی / Persistence

`DataStore (Preferences)` — کاملاً آفلاین، بدون حساب کاربری:
سکه، جواهر، بهترین امتیاز، بلندترین طبقه، مجموع سکه‌ها/صعودها/دشمنان، پوسته‌های باز‌شده،
پوسته‌ی فعال، سطح ارتقاها، دستاوردها، ۱۰ رکورد آخر و همه‌ی تنظیمات.

**تصمیم طراحی (تعادل):** طبق مکانیک «سکه‌ها با مرگ از دست می‌روند»، پس از سقوط به‌صورت
پیش‌فرض ۴۰٪ سکه‌های همان صعود باقی می‌ماند و با خرید ارتقای **بیمه سکه** ۱۰۰٪ حفظ می‌شود
(نگه‌داشتن ۰٪ پیشرفت را غیرممکن می‌کرد).

## ۸. درآمدزایی / Monetization (اختیاری و قابل حذف)

* `AdProvider` — رابط مستقل از SDK. پیاده‌سازی فعال: `MockAdProvider` (ویدیوی جایزه‌دار
  شبیه‌سازی‌شده برای «ادامه از همین طبقه» و «دو برابر کردن سکه‌ها»). هیچ SDK تبلیغاتی گوگلی
  در پروژه نیست.
* `BillingProvider` — رابط مستقل از فروشگاه. پیاده‌سازی فعال:
  **`BazaarBillingProvider`** با SDK رسمی کافه بازار (**Poolakey**). اگر بازار روی دستگاه نصب
  نباشد، به `UnavailableBillingProvider` برمی‌گردد و بازی بدون هیچ خطایی ادامه می‌یابد.
* هیچ بخشی از گیم‌پلی پشت پرداخت قفل نیست.

## ۹. انتشار در کافه بازار / Cafe Bazaar release

### Signing

کلید انتشار **هرگز** در گیت نیست (`.gitignore` شامل `*.jks` و `keystore.properties`).

```bash
keytool -genkeypair -v -keystore eviltower-release.jks -alias eviltower \
        -keyalg RSA -keysize 2048 -validity 10000 \
        -dname "CN=Evil Tower, OU=Games, O=Hadipoor, L=Tehran, S=Tehran, C=IR"

cp keystore.properties.example keystore.properties   # سپس مقادیر واقعی را وارد کن
./gradlew assembleRelease
```

در GitHub Actions مقادیر از Secrets خوانده می‌شوند:
`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`
(اگر تنظیم نشده باشند، ورک‌فلو یک کلید موقتِ فقط-برای-تست می‌سازد و در لاگ هشدار می‌دهد؛
برای انتشار واقعی حتماً Secrets را تنظیم کن تا امضای همه‌ی نسخه‌ها یکسان بماند).

### کلید پرداخت بازار

```bash
export BAZAAR_RSA_KEY="<RSA public key از پیشخوان بازار>"
./gradlew assembleRelease
```

### به‌روزرسانی

هیچ API به‌روزرسانی گوگل (In-App Update) استفاده نشده است. **تصمیم:** به‌روزرسانی کاملاً بر
عهده‌ی خود کافه بازار گذاشته شده تا نه به سرور اضافی نیاز باشد و نه به سرویس‌های گوگل.

### بسته‌ی فروشگاه

## ۱۰. تست‌ها / Testing

```bash
./gradlew test
```

* `FloorGeneratorTest` — تعیّن (determinism) خروجی، وجود زمین و سکوها در هر ۱۰۰ طبقه،
  **قابل‌رسیدن‌بودن هر سکو** (فاصله‌ی عمودی ≤ ارتفاع پرش، فاصله‌ی افقی ≤ برد پرش)،
  ماندن سکوها داخل دیوارها، درست‌بودن طبقات باس.
* `CollisionTest` — تقاطع AABB، فرود روی زمین، پرش و جاذبه، مرگ در اثر سقوط، توقف بازی.
* `EngineSimulationTest` — یک **ربات صعودکننده** روی چند seed بازی می‌کند و باید حداقل به
  طبقه ۳ برسد؛ اگر تغییری برج را غیرقابل‌عبور کند این تست می‌شکند.
